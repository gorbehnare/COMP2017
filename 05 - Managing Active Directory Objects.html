05 - Managing Active Directory Objects

Source: Microsoft Learn: Create and manage Active Directory objects

As a system administrator, you must manage infrastructure by controlling access for users, systems, and services. Some of the system administration tasks and responsibilities include:

  • Define users, groups, and computers.
  • Define organizational units.
  • Create, configure and manage objects and their properties in Active Directory.
  • Perform bulk management tasks
  • Maintain AD DS domain controllers.

Active Directory Object Types

AD DS has several types of account and group objects, such as users, groups, managed service accounts, and group managed service accounts. Several tools can be used to manage these objects in AD DS:

  • Active Directory Administrative Center (ADAC).
  • Active Directory Users and Computers (ADUC).
  • Windows Admin Center (WAC).
  • Windows PowerShell with the Active Directory PowerShell module.
  • The dsadd command-line tool for managing users, groups, and computers (Legacy).

The following provides basic information about related object types in AD DS.

Users

In Windows Server, a user account is an object that contains all the information that defines a user. A user account object includes:

  • The username.
  • A user password.
  • Group memberships.

The username and password of a user account serve as the user’s sign-in credentials. A user object also includes several other attributes that describe and manage the user.

Group Objects

Groups are used to simplify management of permissions and access controls for users and enable bulk management of permissions. There are two types of group objects:

  • Security groups: used to assign permissions to various resources; can be used in ACLs or to use a group to manage security.
  • Distribution groups: objects designed exclusively for email distribution and cannot be used to assign permissions to network resources.

The groups also contain a scope:

  • Local: assign abilities and permissions on local resources on the local computer.
  • Domain-local: assign abilities and permissions on all computers in the local domain.
  • Global: assign abilities and permissions anywhere in the forest, but their membership is generally limited to accounts and other global groups from the same domain.
  • Universal: used in multi-domain networks, assigns abilities and permissions anywhere in the forest, while the member can be from anywhere in the AD DS forest.

Managed Service Accounts (MSA)

Usually when software is installed on a host, it uses local user accounts to execute and manage the associated Windows services. Usually a regular user Account is created and the service is configured to use this user account to run. A regular user account used as a Service Account, requires manual credential management and maintenance (passwords are set manually). These Service Accounts can be a local user, domain user, or built-in or virtual user account.

If centralized management of Service Accounts is required, then Windows Server supports an AD DS object named Managed Service Account (MSA). An MSA is an AD DS object class that enables:

  • Automatically sets and periodically renews passwords
  • Automatically generates and manages SPN
    • SPNs are the unique IDs that are used to locate the correct account in the AD DS database during the Kerberos authentication process

MSA can only be used on a single server.

Group Managed Service Accounts (gMSA)

Group managed service accounts enable the capabilities of standard MSA to be extended to more than one server in a domain. Multiple servers can be placed in a group that can be configured to use the same accounts to simplify and reduce administration overhead of using MSA.

  • gMSAs support:
    • Multiple servers
    • Automatic password management
    • Simplified SPN management
    • Delegated administration
  • gMSAs are commonly used in:
    • Server farms
    • Load-balanced applications
    • Multi-server applications requiring a shared identity.

Computer Objects

Computer objects are security principals in AD DS that:

  • They have an account with a sign-in name and password that Windows changes automatically periodically.
  • They authenticate with the domain.
  • They can belong to groups and have access to resources, and can be configured by using Group Policy.

Computer accounts are created when a computer joins a domain. Administrators with appropriate privileges can:

  • Configure computer properties.
  • Move the computer between OUs.
  • Manage the computer itself (via Group Policy).
  • Take actions such as rename, reset, enable/disable, and delete the computer object.

Computer Containers and Other Generic Containers

Computers container is a built-in "generic container" in an AD DS domain and is the default location (parent object) for the computer accounts when a computer joins the domain. The Computers container cannot have Group Policy Objects linked directly to it and does not provide the delegation capabilities of an OU, making it less suitable for administration. It is recommended to move the computer objects into OUs (Organizational Units) where they can be bulk managed as groups. OUs enable delegation of authority and group policies to be applied to the computer objects.

Other generic containers are created when other features are enabled and act as the default parent object to store new objects. Containers have limited management capabilities, and some are hidden by default. As an example, A new AD DS installation creates the Domain Controllers OU and several built-in containers, such as:

  • Domain: The top level of the domain organizational hierarchy.
  • Builtin container: A container that stores several default groups.
  • Computers container: The default location for new computer accounts that you create in the domain.
  • Foreign Security Principals container: The default location for trusted objects from domains outside the local AD DS domain that you add to a group in the local AD DS domain.
  • Managed Service Accounts container: The default location for managed service accounts. AD DS provides automatic password management in managed service accounts.
  • Users container: The default location for new user accounts and groups that you create in the domain. The Users container also holds the administrator and guest accounts for the domain, and some default groups.
  • Domain Controllers OU: The default location for domain controllers' computer accounts. This is the only OU that is present in a new installation of AD DS.

Organizational Units

An organizational unit (OU) is a container object within a domain that can be used to consolidate users, computers, groups, and other objects. Group Policy Objects (GPOs) can be directly linked to an OU to manage the users and computers contained in the OU. Additionally, an OU can be used to delegate administrative control of the contained objects to a user or a group.

OUs can be used to represent hierarchical and logical structures within your organization. For example, you can create OUs that represent the departments within your organization, the geographic regions within your organization, or a combination of both departmental and geographic regions. Once the hierarchy of OUs is created, all other objects added to OUs can be managed consistently and in bulk.

AD Object Management Tools

Active Directory Administrative Center (ADAC)

A GUI tool that is based on PowerShell. Can be accessed via Server Manager > Tools > Active Directory Administrative Center.

Tasks that can be performed via Active Directory Administrative Center:

  • Create and manage users, computers, groups, and OUs
  • Connecting to and managing multiple domains
  • Searching and filtering AD DS data by building queries.
  • Creating and managing fine-grained password policies.
  • Recovering objects from the Active Directory Recycle Bin.
  • Managing objects that the Dynamic Access Control feature requires.

Active Directory Users and Computers (ADUC)

Microsoft Management Console (MMC) snap-in that manages most common resources, including users, groups, and computers. Although many administrators are familiar with this snap-in, the Active Directory Administrative Center replaces it and provides more capabilities. Can be accessed via Server Manager > Tools > Active Directory Users and Computers.

Windows Admin Center (WAC)

Windows Admin Center (WAC) is a browser-based management tool from Microsoft that provides a unified interface to manage servers, clusters, hyper-converged infrastructure, and Windows PCs. It intends to replace legacy tools such as Server Manager and MMC snap-ins and eventually the Remote Server Administration Tools (RSAT) with a modern, extensible gateway architecture.

This tool needs to be downloaded and installed on a Windows system, either a member server or a domain-joined and preferably hardened workstation. Installing Windows Admin Center on a Domain Controller is not supported by Microsoft and is not recommended from a security standpoint.

WAC can be installed in Gateway mode for multi-user access on a server (defaults to HTTPS port TCP 443, but configurable during installation) or Desktop mode for single-user access on a workstation, and defaults to TCP 6516. The user accessing WAC must have Administrative privileges. The target server must have WinRM service enabled and listening (TCP 5985 for HTTP or TCP 5986 HTTPS). PowerShell remote access is also used for execution of scripts.

Windows PowerShell with the Active Directory PowerShell module

The Active Directory module for Windows PowerShell supports AD DS administration and can perform almost all management tasks. The Server Manager and the Active Directory Administration Center are based on Windows PowerShell and use cmdlets to perform their tasks, so essentially they are a GUI front-end for running PowerShell commands on the back-end.

Active Directory PowerShell module can be installed on Windows Server via Server Manager or PowerShell using Install-WindowsFeature -Name RSAT-AD-PowerShell. This is usually installed by default on the Domain Controller as a dependency. On Windows 11 client PCs, this module can be installed via the GUI using Settings > Apps > Optional Features, or using PowerShell.

The dsadd CLI Tool (Legacy)

The dsadd command-line tool is a legacy Windows utility used to add specific objects (users, groups, computers, OUs, contacts, quotas) to Active Directory Domain Services (AD DS) or Active Directory Lightweight Directory Services (AD LDS). It is included by default with the AD DS role and can be installed in client systems using Remote Server Administration Tools (RSAT). While it may still be functional in Windows Server 2025, dsadd is considered a legacy tool. Microsoft recommends using the Active Directory module for Windows PowerShell or Windows Admin Center instead.

Syntax: dsadd <object_type> <DistinguishedName> [options]
Example: dsadd user "CN=John Doe,CN=Users,DC=corp,DC=com" -samid jdoe -pwd P@ssw0rd
