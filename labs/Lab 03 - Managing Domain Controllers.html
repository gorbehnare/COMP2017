Additional Recommendations:

  • It is recommended that you create a new snapshot for each of your VM’s to have an easy restore point that can be used later in the course.
  • Use a snapshot naming convention that is easy for you to understand. For example: DC1-before-Lab03
  • If you have enough storage on your system, you can create full clones of Windows VMs before making changes or to experiment and test changes before you apply them.
    • Ensure you keep the MAC address, clone the hardware IDs and other IDs so you do not need sysprep. However, do NOT start the clones at the same time (obviously this will cause many types of conflicts if you start/run the Cloned VMs at the same time).
    • This will allow you to freely create and then delete the VMs as desired in a disposable manner while keeping the original VM intact.
      • WARNING: Please note that, even if you are cloning the VM, the changes you make to the domain members are reflected in the domain controller, and not within the local VMs. For example, if you leave the domain in the clone, delete the clone and start the original VM, you will have to rejoin the original VM to the domain since the trust relationship may be broken.
        • This is a good practice and learning experience to reinforce your knowledge about where the changes are being made. Additionally, you will learn at what point in the lab procedures you will switch back from the clone to the original VM during cleanup!
  • Shut down the VMs from within the guest OS; do NOT use pause. Do not let your laptop go to sleep or run out of battery while running VMs. Make sure to connect your computer to power and do not run on battery.

Adding a Domain Controller to an Existing Domain

In this exercise, you will use the TOR-2017-#### server to create a second domain controller for the comp2017-####.local domain.
As a matter of recommended best practices, every Active Directory domain environment should have a minimum of two domain controllers to provide redundancy and avoid a single point of failure. Microsoft recommends installing a secondary DNS server as well, however, for this lab, our system will be pointing to a DNS server on DC1-2017-####. It is best that the server is joined to the domain.

  • Log on to TOR-2017-#### as the domain administrator comp2017-####\administrator. To confirm that you have logged in to the correct account, start PowerShell and execute the whoami command.
  • In the Server Manager use the Add roles and features wizard to install Active Directory Domain Services and DNS Server
  • Once the installation is completed, you should see a Post-deployment Configuration warning on the notification flag. Sometimes you may have to use the Refresh button. Click the yellow triangle with the black exclamation point and then click Promote this server to a domain controller.
  • In the AD DS configuration Wizard, use the Add a domain controller to an existing domain radio button, and ensure the domain name is correct.
  • Under the Domain Controller Options configuration page, make sure that the following capabilities are selected using check boxes:
    • Domain Name System (DNS) server and Global Catalog (GC)
    • Set the Directory Service Restore Mode (DSRM) to something that you remember (in production, use secure passwords and store them in a secure vault such as a password manager)
  • Click Next the defaults on the DNS Options, and observe the available options for the Replicate from: drop-down under Additional Options. Leave the default Any domain controller selected, but the FQDN for the DC1-2017-#### should also be listed.
  • Complete the installation and allow the server to reboot.
  • Log in using your domain administrator comp2017-####\administrator account.
  • In Server Manager, open Tools > Active Directory Users and Computers.
  • Expand the comp2017-####.local node and then click the Domain Controllers node.

Moving Operations Masters to TOR

In this exercise, you will transfer the Operations Masters between domain controllers. This is useful for scheduled maintenance and planned downtime where operations masters will be unavailable. Downtime will affect some operations, which may be noticed by end-users and will prevent some administrative tasks. You should move the operations masters to other domain controllers that will be available during the maintenance period to maintain availability and functionality of your system.

As a reminder, there are five operations masters:

  • RID operations master
  • PDC Emulator operations master
  • Infrastructure operations master
  • Domain naming operations master
  • Schema operations master

Transfer RID, PDC, and Infrastructure Operation Masters to TOR

  • Log on to TOR-2017-#### as the domain administrator comp2017-####\administrator.
  • In Server Manager, open Tools > Active Directory Users and Computers.
  • Right-click comp2017-####.local and choose Change Domain Controller. Click TOR.comp2017-####.local and then click OK.
  • Right-click comp2017-####.local and choose Operations Masters....
  • To change the RID from DC1.comp2017-####.local to TOR.comp2017-####.local, click the Change... button on the RID tab. When you are prompted to confirm this action, click Yes. When the Operations Master role is transferred, click OK.
  • Click the PDC tab and transfer the PDC to TOR-2017-#### using the same process.
  • Click the Infrastructure tab and transfer the operation master to TOR-2017-#### using the same process.
  • Close the dialogue box and the Active Directory Users and Computers console.

Change Schema Operations Master to TOR

The Active Directory Schema snap-in is not available by default in MMC, even on many domain controllers. The schmmgmt.dll is the DLL for the Active Directory Schema MMC snap-in. To register and activate the snap-in, use the Regsvr32.exe utility as follows:

  • At the command prompt, execute: Regsvr32 schmmgmt.dll
  • When the schmmgmt.dllis registered, click OK.

Launch MMC and use the Active Directory Schema snap-in:

  • At the command prompt, execute the mmc command. The MMC console opens.
  • Click File > Add/Remove Snap-in, select Active Directory Schema, and then click Add. Click OK to close the dialogue box.

To transfer the schema master:

  • In the left pane, right-click Active Directory Schema and choose Connect to Schema Operations Master.
  • Right-click Active Directory Schema and choose Change Active Directory Domain Controller. Click TOR.comp2017-####.local and then click OK. When a warning displays, click OK.
  • Right-click Active Directory Schema and choose Operations Master. The Change Schema Master dialogue box opens. Change Schema Master to TOR-2017-####.

Seizing Operations Masters Back to DC1

In this exercise, instead of transferring the Operations Master, you will seize the Operations Masters and move them to another domain controller. It is always preferable to transfer roles instead of seizing roles. Transferring roles is done when the current operations masters are available. Seizing a role is done when the operations masters are unavailable for a lengthy period of time, or in case of unplanned downtime.

In this example, we are using ntdsutil, which is considered a legacy tool. It is still included in Windows Server 2025 but may be removed in the future. It is recommended that you use PowerShell of the GUI tools for these operations in a production environment. However since the ntdsutil tool has been around since 2000 and had been used for such a long time, it is being used for demonstrative purposes.

Ensure all the commands you execute complete successfully. Future assignments require that the system is restored as detailed in this challenge. Pay close attention to the computer names you use in the command lines.

  • Log on to DC1-2017-#### as comp2017-####\administrator. To confirm that you have logged in to the correct account, start PowerShell and execute the whoami command

  • From a new PowerShell window, execute the ntdsutil CLI program.

  • At the ntdsutil prompt, execute the roles command. Your prompt will change to fsmo maintenance:.

  • At the fsmo maintenance: prompt, execute the connections command.

  • At the server connections: prompt, execute the following command. Remember to specify the correct hostname for your environment:

    • connect to server DC1-2017-####
    • If successful you should see Binding to DC1-2017-#### as output.

  • Exit the server connections: prompt using quit to go back to the fsmo maintenance: prompt

  • From this point, you can transfer or seize operations master. To get the correct syntax and available options, use the ? or help.

  • To seize the roles, at the fsmo maintenance prompt, type the following commands, clicking Yes each time you’re prompted to confirm:

    •   seize schema master
  seize naming master
  seize RID master
  seize infrastructure master
  seize PDC
