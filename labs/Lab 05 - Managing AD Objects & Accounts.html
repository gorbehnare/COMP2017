Creating a Single User Account in Active Directory Users and Computers

A user account is used by Windows to determine which changes can be made on the computer, which files and folders you have access to, and which user preferences you might have (such as your choice of desktop wallpaper, colour schemes, drive mappings, and/or screen savers). There are standard accounts used to perform daily tasks on the computer that are limited in what they can do, as well as administrative accounts that provide full control over the computer. In this exercise, you will use the Active Directory Users and Computers console to create and manage a domain user account.

Creating a Service Account

A service account is an account that an operating system, process, or service runs under. A service account can grant the application or service the specific rights and permissions it needs to function properly while minimizing the permissions required for users of the application server. Service accounts are used to run Microsoft Exchange, Microsoft SQL Server, Internet Information Services (IIS), and SharePoint. In this exercise, you will create a traditional service account and then use the account with a service.

  • On DC1-2017-#### , in Server Manager, click Tools > Active Directory Users and Computers.
  • Create a new OU under comp2017-####.local:
    • Right-click comp2017-####.local and chooseNew > Organizational Unit
    • Name the new OU as Service Accounts.
  • Create a new user under the Service Accounts OU:
    • First name: App1
    • User logon name: App1Service
    • Password: Password01 (Notice: This is a BAD IDEA for a production environment. Use strong and random passwords, do not reuse passwords, and use a secure vault to store passwords)
    • Select the Password never expires option

Start your SRV1-2017-#### VM if not already started.

  • Log on to SVR1-2017-#### as the domain administrator comp2017-####\administrator.
  • In Server Manager, open Tools > Services.
  • Scroll down to the SNMP Trap service, and double-click to open properties.
  • Click the Log On tab, and under This account, change the account credentials to the new service account you have created in the last step:
    • account: comp2017-####\app1service (To verify everything is correct, click the Browse... button, enter the name in the box and click the Check Names button)
    • Password: Password01, and repeat to confirm.
  • Click Apply, and observe the warning. Click OK. Click OK to exit the service properties.
  • Right-click the SNMP Trap service and choose Start.

Creating a Managed Service Account

Rather than manually changing the account password and the password for the service or application, you can use a Managed Service Account (MSA), in which the password automatically changes on a regular basis. We will be using the existing group to avoid having to assign MSA to every server individually. This is the recommended approach in production because new servers can be added to the group without reconfiguring the gMSA.

Create a Security Group for Authorized Servers:

  • On DC1-2017-####, open Active Directory Users and Computers.
  • Create a new Group under the Computers container named ServerGroup:
    • Right-click the Computers container and choose New > Group, and set the group name to ServerGroup.
    • Notice the default Group scope, but leave it as Global
  • In the Computers container, right-click ServerGroup and open Properties.
  • On the Members tab, then click Add....
  • Click Object Types, select only Computers, and then click OK.
  • Under the Enter the object names to select text box, type the hostname for SVR1-2017-####, and click the Check Names button to validate the hostname.
  • Click OK to add the host as a member of the group, and Apply and close the ServerGroup Properties dialogue box.

Create A Root Key:

    Add-KDSRootKey –EffectiveTime ((Get-Date).AddHours(-10))

Kerberos Policy Settings

Kerberos is the default authentication mechanism in an Active Directory Domain Services (AD DS) environment and plays a critical role in authorization and auditing. Because Kerberos is used as part of the Active Directory domain, Kerberos settings can be configured only at the domain level with a GPO. In this exercise, you will observe Kerberos Policy settings using the default domain policy.

  • Log on to DC1-2017-#### as the domain administrator comp2017-####\administrator.
  • In Server Manager, open Tools > Group Policy Management.
  • In the Group Policy Management console, expand Forest: comp2017-####.local > Domains > comp2017-####.local.
  • Click Default Domain Policy. If you are prompted with a notification, click OK to continue. You should see the Default Domain Policy overview page.
  • Right-click Default Domain Policy and choose Edit. The Group Policy Management Editor opens.
  • In the left pane, expand Computer Configuration > Policies > Windows Settings > Security Settings > Account Policies and then select Kerberos Policy.

    Review the policy settings meaning using Microsoft documentation for Kerberos Policy.

Most system admins leave these values as their default for their production systems. Modify the following configuration just to experience what the configuration window looks like:

  • Maximum tolerance for computer clock synchronization: Change to 4 minutes.
    • Check out the Explain tab, and notice the default documented value.
  • Maximum lifetime for user ticket: Change to 8 hours
    • Check out the Explain tab, and notice the default documented value.

Configuring a Domain Password and Lockout Policy

You can define account policies only for domain users at the domain level, which include the password policy, the account lockout policy, and the Kerberos policy. In this lab challenge, you will explore and view the domain-level password policy, including configuring maximum password length and password history.

  • On DC1-2017-#### , In Server Manager, click Tools > Group Policy Management.
  • Navigate to and select the Default Domain Policy. Right-click the Default Domain Policy and choose Edit; the Group Policy Management Editor opens.
  • In the left window pane, expand Computer Configuration > Policies > Windows Settings > Security Settings. In the Security Settings node, expand Account Policies.
  • Select Password Policy to view the current configuration, such as maximum password age, minimum length, etc.
  • Attempt to change the Minimum password length to the minimum recommended by NIST SP 800-63 B Rev. 4 of 15 characters when MFA is not enabled. Are you able to set these settings?
  • Use the Explain tab to find out what is preventing you from selecting 15 or more characters. Make the appropriate change to policies to allow you to enforce Minimum password length of 15 characters.

Take a full window SCREENSHOT of the Group Policy Management Editor window, showing that you have set the Minimum password length to 15 characters.

  • Navigate to Account Lockout Policy and view the default settings. How many invalid login attempts result in an account being locked by default? Look at the Explain tab for each item to validate your findings.
  • Attempt to change the policy so an account will be locked out after 5 invalid logon attempts. Observe what other policies are being enabled by default and their values.
