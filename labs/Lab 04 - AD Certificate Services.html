Lab 04 - AD Certificate Services

Install Certificate Authority (CA) on DC1

  • Log on to DC1-2017-#### and domain admin (comp2017-####\Administrator):
  • Using the Server Manager → Manage → Add Roles and Features wizard, select the following role:
    • Active Directory Certificate Services
    • Proceed through the wizard and under the Select role services page, select the following additional services:
      • Certification Authority
      • Certification Authority Web Enrollment
      • Certificate Enrollment Web Service
  • Reboot the server if required.
  • Using the Notifications Flag or on the AD CS screen, configure the Certification Authority using the following options through the wizard:
Option Value
Setup Type Enterprise CA
CA Type Root CA
Private Key Create New Private Key
Crypto Options RSA#Microsoft Software Key Storage Provider
Key Length 4096
Hash Algorithm SHA512
Validity Period 5 Years
  • Use the default values for other settings and finish the configuration.
  • Select Yes when you are prompted if you would like to configure additional Role Services.
  • The AD AS Configuration wizard will open again, and this time select Certificate Enrollment Web Services.
    • Follow the wizard. You may select Use the built-in application pool identity.
    • Select your existing CA cert that you created in the last step and complete the configuration wizard.
  • Repeat the same steps for Certificate Authority Web Enrollment.
  • Open the Server Manager, and navigate to the AD CS page from the left side of the window. Scroll down to ROLES AND FEATURES and take a SCREENSHOT of this window. The screenshot should clearly show the following:
    • There should be no errors or warnings or pending configuration notifications at this point. You may see information about your completed installations.
    • The 4 total roles and role services related to AD CS must be listed.

Request a Certificate via Web Enrollment (Legacy)

You can use the Certificate Authority Web Enrollment using the Microsoft Edge browser. Unfortunately, this site is a legacy site and only works in Internet Explorer. Microsoft Edge comes with IE mode, which should allow you to load this site.

  • In Microsoft Edge. navigate to https://dc1-2017-####.comp2017-####.local/certsrv (replace the #### with last 4 digits of your student ID)
  • You should be prompted for your credentials in a pop-up window. Use your domain administrator account to authenticate.
  • Once you have logged in, take a SCREENSHOT of your Microsoft Edge browser with the following information visible:
    • Complete URL visible and should have your hostname and domain name.
  • Here is an example:
  • Optional Step: If you have managed to load the page in IE mode in Microsoft Edge, you can proceed to generate a certificate for your user. This page uses legacy ActiveX, which is no longer supported in most modern operating systems. Once you navigate through the prompts, you will see the option to Install this certificate on the system.

This method of obtaining and installing certificates has been replaced with the following methods:

  • Domain-joined computers and users use the Group Policy Auto-Enrollment to automatically generate user and system certificates
    • Use the Certificate Services Client – Auto-Enrollment policy
  • Non-Domain systems, such as mobile devices, Linux, macOS, and other operating systems:
    • Use the Network Device Enrollment Service (NDES) role to provide Simple Certificate Enrollment Protocol (SCEP) over HTTPS. This requires software that supports the protocol on the target device, or management software such as Microsoft Intune.
  • Programmatic enrolment API through Certificate Enrollment Web Services.
    • Interface URL is at https://<server_FQDN>/certsrv/certfnsh.asp
    • Eliminates dependency on ActiveX, uses HTTPS and SOAP for API access
    • Access using certreq -policyserver CLI utility from PowerShell, or 3rd party utilities that can make appropriate API calls

View Trusted Root CA Certs and Their Expiry Dates

In Windows, you can view the Trusted Root CA Certificates using the following method:

  • In PowerShell, execute mmc.exe (Microsoft Management Console)
  • Add the required snap-in by navigating using the menus: File > Add/Remove Snap-in....
  • Select Certificates on the left and use the Add > button. You will be asked for the scope for this item, such as your user account, the local system service account, or a computer (which can be a local or remote computer).
  • Add the snap-in to manage My user account on a stand-alone system.
  • From there, you can expand Certificates to find Trusted Root Certification Authorities and view and manage the root CA certificates on your system.

    These are all the CA signatures that your system will automatically trust on any certificates from any sources while you are using your user account.
  • You can also repeat the same process to add another snap-in for the Certificates on your local computer.
  • If you are using your lab VM with correctly installed and configured AD CS services, you should also find your CA certificate in this list.
    • You can also view another snap-in called Enterprise PKI as a quick view for the status of current certificates within your PKI.
