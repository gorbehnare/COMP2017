Restoring a Deleted Object Using the Recycle Bin

Similar to the Windows Recycle Bin, deleted objects are stored in a deleted folder. For a period of time after an Active Directory object is deleted, an administrator can undelete it, restoring it to its original state. In this exercise, you will activate the Active Directory Recycle Bin. You will then delete an object and restore the object from the Recycle Bin.

Enable Recycle Bin for Your AD Domain

  • On DC1-2017-####, log on as comp2017-####\administrator.
  • In Server Manager, click Tools > Active Directory Administrative Center. The Active Directory Administrative Center opens.
  • Click comp2017-#### (local). In the right pane, click Enable Recycle Bin. When a message indicates that the Recycle Bin cannot be disabled once enabled and prompts you to confirm, click OK.
  • Refresh [ ] the Active Directory Administrative Center. Keep this window open for the next steps.

Test the Recycle Bin

  • In the Active Directory Administrative Center, click the small arrow next to the comp2017-#### (local) domain and select Sales OU.
  • Find and delete the Abbie Parsons user object. Click Yes to continue.
  • In Active Directory Administrative Center, click the small arrow next to the comp2017-#### (local) domain and double-click Deleted Objects. If the Abbie Parsons account does not show in the Deleted Objects folder, refresh and try again.

Replicating with Active Directory Sites and Services

Replication occurs between domain controllers within a site (intrasite replication) or between domain controllers in separate sites (intersite replication). In this exercise, you will replicate Active Directory between two domain controllers using the Active Directory Sites and Services console.

  • Log on to SVR1-2017-#### as comp2017-####\administrator. Install the Active Directory Domain Services role on this system as follows:

    • In Server Manager, click Manage > Add Roles and Features.
    • In the Add Roles and Features Wizard, click Next.
    • On the Select installation type page, click Next.
    • On the Select destination server page, click Next.
    • On the Select server roles page, click Active Directory Domain Services. When you are prompted to confirm you want to add features, click Add Features.
    • Back on the Select server roles page, click Next.
    • On the Select features page, click Next.
    • On the Active Directory Domain Services page, click Next.

  • On the Confirm installation selections page, click Install.

  • When Active Directory Domain Services is installed, click Close.

  • In Server Manager, click the notification flag with the yellow triangle and black exclamation point (!) and then click Promote this server to a domain controller:

  • In the Active Directory Domain Services Configuration Wizard, Add a domain controller to an existing domain is already selected. Ensure that the domain text box shows comp2017-####.local. Click Next.

  • On the Domain Controller Options page, answer the following question. Then, in the Password text box and the Confirm password text box, type a DSRM password that you will remember and then click Next.

  • On the DNS Options page, click Next.

  • On the Additional Options page, click Next.

  • On the Paths page, click Next.

  • On the Review Options page, click Next.

  • On the Prerequisite Check page, click Install when the check is finished.

  • After a couple of minutes, Windows will reboot. Wait for the reboot to complete.

  • Switch to DC1-2017-####, and log in as comp2017-####\administrator.

  • In Server Manager, open Tools > Active Directory Sites and Services.

  • In Active Directory Sites and Services, drill down to Sites > Default-First-Site-Name > Servers, expand DC1-2017-####, and then click NTDS Settings.

  • Open the Action menu and click Refresh, or click the refresh button, until the SVR1-2017-#### entry appears.

  • If the entry does not appear after a few minutes, log in to SVR1-2017-#### as the domain admin, open Server Manager > Tools > Active Directory Sites and Services, then drill down to the Sites > Default-First-Site-Name > Servers > SVR1-2017-####, select NTDS Settings, right-click on <automatically generated>, and select Replicate Now.

  • Go back to DC1-2017-#### and refresh again.

Backing up and Restoring Active Directory

The system state is a collection of system components that make up major components of Windows that cannot be easily backed up. It includes boot files, the registry, SYSVOL, Active Directory database, Certificate store, and IIS metabase. When restoring Active Directory, there are nonauthoritative restores and authoritative restores. When a nonauthoritative restore is performed, Active Directory overwrites the old data that is restored from backup. To restore old data as data that you want to keep, you need to perform an authoritative restore.
As a system administrator, it is important to have good backups. In this lab challenge, you will use Windows Server Backup to back up the system state of DC1-2017-####, which will include Active Directory. You will then restore the Sales OU.

  • Install the Windows Server Backup feature on DC1-2017-####:

  • In Server Manager, click Manage > Add Roles and Features.

  • In the Add Roles and Features Wizard, click Next.

  • On the Installation Type page, click Next.

  • On the Server Selection page, click Next.

  • On the Server Roles page, click Next (do not select or change anything).

  • On the Features page, click to select Windows Server Backup, then click Next, and then Install on the confirmation page. You can close the page and wait for the installation to complete.

  • Switch to SVR1-2017-####, and create a shared folder as the domain admin (comp2017-####\administrator):

  • Create a directory C:\BAK.

  • To share the directory, right-click the C:\BAK folder and choose Properties. Navigate to the Sharing tab and click the Advanced Sharing ... button.

  • In the Advanced Sharing dialogue box, click the Share this folder check box.

  • Click the Permissions button. For Everyone, click to select Allow for the Change permission. Click 'OK' and Apply where appropriate to apply the settings and close the dialogue boxes.

  • You can see the network path to this directory by looking at the Properties and Sharing tab for C:\BAK on SVR1-2017-####. For example, the network share path should be \\Srv1-2017-####\bak. You can copy or record this path from your system for the next steps.

Performing Backup

  • Switch back to DC1-2017-#### to make sure you can navigate to the new shared directory in Windows Explorer using the share path. You should see an empty directory at this point.
  • On DC1-2017-####, in Server Manager, click Tools > Windows Server Backup. The Windows Server Backup console opens.
  • Click on Local Backup in the left pane to select, and then click on Actions > Backup Once... in the menu. The Backup Once Wizard will open.
  • The Different Options radio button should already be selected; click Next.
  • On the Select Backup Configuration page, observe the reported backup size of you were to take a Full server backup. However, for now, select the Custom option and then click Next.
  • On the Select Items for Backup page, click Add Items. Observe the available options that you can select.
  • Select the System state and then click OK. Then click Next.
  • On the Specify Destination Type page, select Remote shared folder. Click Next.
  • On the Specify Remote Folder page, enter the path to your shared directory on your SVR1-2017-#### system; for example, type \\Srv1-2017-####\bak and then click Next.
  • On the Confirmation page, click Backup.

NOTE: the backup may take a significant amount of time. You should see that the system collects files to include in the backup before transferring files to the backup location. Keep the Backup Progress window open. Wait for the backup process to complete.

Restore From Backup

In this section, we will be performing an authoritative restore of the AD on DC1-2017-#### using the backup you just took.

  • On DC1-2017-####, click the Start button, type msconfig, and then press Enter.

  • In the System Configuration window, open the Boot tab, check the Safe boot checkbox, then select the Active Directory repair radio button as shown below:

  • Click on OK, and when prompted, click Restart. The system should boot into Safe Mode.

  • Log on to DC1-2017-#### as the local administrator: On the logon screen click on Other User in the corner, and use username Administrator and your local admin password. Verify that your system is booted in Safe Mode (Safe Mode is displayed in the 4 corners of your desktop).

  • Open the Server Manager and click Tools > Windows Server Backup. The Windows Server Backup console opens.

  • Select the Local Backup, and click on Action > Recover....

  • In the Recovery Wizard, select A backup stored on another location and then click Next >.

  • Select the Remote shared folder and then click Next >.

  • On the Specify Remote Folder, type your path to our shared directory, \\Srv1-2017-####\bak, and then click Next >.

  • You should see available system state backups based on the date and time you completed the backup. Select your backup and click Next >.

  • On the Select Recovery Type page, select System state and click Next \\Srv1-2017-####\bak.

  • On the Select Location for System State Recovery page, select the Original Location and check the Perform an authoritative restore of Active Directory files. checkbox, and then click Next >.

  • You will be prompted with two dialogue windows; select OK and close them to get to the Confirmation page.

  • On the Confirmation page, click the Recover button. Accept the warning that this process cannot be interrupted.

  • Wait for the process to complete.

NOTE: the restore may take some time, however it may be faster than the backup process. Do NOT close or restart the system before taking the required screenshot! While the restore is in progress, you can see the list of various items being restored and their detailed progress.

Take a SCREENSHOT of the completed recovery progress at the point where it is prompting you to restart. Here is an example:

  • Click the Restart button and let the system reboot.
  • Log back in as the local Administrator.

NOTE: After the first restart your domain is still not available, because the restore process is not yet completed. The system boots back into Safe Mode.

  • Once you log back in, there should be a Windows CMD open as follows:
  • Press Enter as instructed, and after a while the window should close by itself.
  • Put the system back to boot into normal mode: Click the Start button, type msconfig, and then press Enter.
  • In the System Configuration window, open the Boot tab, and remove the Safe boot checkbox. Restart the server to go back to normal mode.
