01 - Introduction to Windows Server

Windows Server History

Windows NT Server

Source: https://en.wikipedia.org/wiki/Windows_Server

Windows Server was conceived in the 1990s to compete with Unix and NetWare, which at the time dominated the business and server market. The first version of Windows NT was released as version 3.1 in 1993 as Server and Workstation flavours. The "NT" was coined as "New Technology" since Windows was rewritten and ported to a native 32-bit architecture, and did not run on DOS. It added new features on top of Windows, such as multi-user support and preemptive multitasking. At this point, only basic TCP/IP stack was included in Windows NT. Windows NT 3.5 Server (1994) included the complete TCP/IP stack and "Winsock" (Windows Socket API), along with FTP.

The start menu interface of Windows 95 was added to Windows NT 4.0, and Windows 2000 introduced Active Directory. Windows NT became the only Windows architecture for consumers and businesses since Windows Server 2003 and Windows XP.

Windows Server Usage

Windows NT was not exclusive to the x86 architecture, as Server and Workstation versions were available for IBM PowerPC, HP PA-RISC, MIPS, DEC Alpha, and other architectures (as well as Intel Itanium later on). In the 1990s, most servers and mainframes did not use x86 architecture. The first Intel Xeon-branded products were released in 1998 as x86 microprocessors for servers and workstations.

The term "Wintel" refers to the partnership between Microsoft and Intel. Intel became the dominating motherboard and chipset manufacturer in the world, and the Microsoft partnership helped in establishing Windows on Intel x86 as de facto standard across the industry (see: https://en.wikipedia.org/wiki/Wintel). This extended into server markets; however, Windows Server usage varies depending on specific use case. Windows Server has less than 10% market share in internet-facing services (see https://w3techs.com/technologies/overview/operating_system), while it has 0% market share in mainframes and supercomputers. On the other hand, Windows Server dominates the SME market where many business applications are based on Windows. According to the "Fortune Business Insights" report from 2026 (https://www.fortunebusinessinsights.com/server-operating-system-market-106601), the overall share of Windows Server OS is around 22%.

Windows Server is typically a requirement for businesses using the following applications:

  • Active Directory
  • Microsoft SQL Server
  • Exchange and Microsoft infrastructure
  • Windows-based business applications

Windows Server 2025

The current version of Windows Server 2025 is based on Windows 11. Windows Server 2025 has the following new features and enhancements:

  • Server Flighting currently only applies to insider builds (preview versions of Windows) and adds the ability to upgrade an existing installation to a new release through Windows Updates, instead of a manual reinstall or upgrade install of the OS.
    • The "flighting" terminology is used by Microsoft to describe progressive rollout, previously applied to Windows 10 and 11 clients, but now applies to Server 2025 as well (see Microsoft Blog Post: Welcome to Windows Insider flighting on Windows Server)
  • Pay-as-you-go subscription option. This requires an Azure subscription and Azure Arc management. See Microsoft Learn article Configure Windows Server Pay-as-you-go with Azure Arc.
  • SMB over QUIC was introduced with Server 2022 Azure Edition, but is now available for all Server 2025 systems (Standard and Datacenter Editions). SMB over QUIC tunnels SMB traffic through a TLS 1.3-encrypted QUIC connection that runs over UDP, usually on port 443. See Microsoft Learn article SMB over QUIC.
    • Additional context for SMB security:
      • SMB Encryption (for data payload in transit) and Pre-authentication Integrity (for protecting session establishment) are separate security features.
      • SMB 3.0 introduced SMB Encryption using AES-128 CCM, but encryption was optional and had to be enabled or required by policy.
      • SMB 3.1.1 introduced mandatory pre-authentication integrity during negotiation, using SHA-512 hashing to protect the negotiation and session setup phases against tampering and man-in-the-middle attacks. AES-128 GCM (in addition to AES-128 CCM, and GCM is recommended) is available for end-to-end encryption for data transmission, but must be explicitly enabled and must be supported by the client.
  • Hotpatching is the process of applying software updates to code that is already running in memory, allowing security and quality fixes to take effect without requiring a system reboot.
    • Instead of replacing files and restarting the operating system to load updated code, hotpatching modifies the active code paths in memory. The primary goals are to reduce planned downtime, increase system availability, and improve security by enabling faster deployment of updates.
    • Hotpatching requires Azure Arc and Virtualization-based Security (VBS/VSM) to be enabled.
  • Windows Package Manager (winget) is included and supported out of the box.
    • The winget utility brings a Linux-style package management experience to Windows, allowing software to be installed, updated, and managed from the command line using a centralized package repository. However, winget does not include OS, libraries, drivers, and other core components. See Microsoft Learn article Use WinGet to install and manage applications.

The Microsoft Azure Arc

Azure Arc is Microsoft's agent-based management platform (Similar to AWS Systems Manager and SSM Agent). It allows management of servers, Kubernetes clusters, databases, and other resources that run outside Azure as if they were Azure resources.

The Azure Arc control plane is included with Azure accounts for free and includes:

  • Registering Windows and Linux servers
  • Viewing servers in the Azure portal
  • Resource groups, tags, and RBAC (Role-Based Access Control)
  • Azure Resource Graph inventory and querying
  • Basic management capabilities

Azure Arc becomes billable when you enable Azure services on top of Arc-connected servers, such as:

  • Azure Update Manager
  • Microsoft Defender for Cloud
  • Azure Monitor / Log Analytics
  • Microsoft Sentinel
  • Azure Automation
  • Azure Policy guest configuration (certain scenarios)

In Windows Server 2025, Azure Arc enables hotpatching and Pay-as-you-go licensing for Windows Server Standard or Datacenter installations.

Windows Server 2025 Editions and Licenses

Windows Server is a proprietary operating system and requires a license to use. Windows Server 2025 introduces updated licensing requirements that differ from previous versions. There are additional Client Access License (CAL) requirements, server license editions, and VM hosting limits that apply when migrating from Windows Server 2016/2019 to Server 2025.

Windows Server 2025 license is offered in the following variants:

  • Windows Server 2025 Standard
    • Core licensing
    • User and Device CALs
  • Windows Server 2025 Datacenter
    • Core licensing
    • User and Device CALs
    • Unlimited VM Rights (with the Core licensing and CAL)
    • Additional advanced features, such as storage spaces, software-defined networking
  • Windows Server 2025 Essentials
    • Only available through OEM channel (sold with physical server)
    • Does not use CALs, supports up to 25 users and 50 devices (not expandable)
    • Not for virtualization and restricted to one bare-metal hardware (the one it was sold with)
  • Windows Server Datacenter: Azure Edition
    • For cloud and hybrid environments, pay-as-you-go, billed monthly

You can see the current retail prices and offerings here: https://www.microsoft.com/en-us/windows-server/pricing#Compareeditions
You can see a detailed comparison of Windows Server editions here: https://learn.microsoft.com/en-us/windows-server/get-started/editions-comparison?pivots=windows-server-2025

The difference between the Standard Edition and Datacenter Edition licensing relevant to our course:

  • The Standard Edition licence is limited to 1 physical host and 2 guest VMs
  • The Datacenter Edition license allows 1 host and unlimited guest VMs

Core Licensing

Windows Server 2025 licenses are sold in 2-core packs. A Standard license covers 16 cores minimum (8 x 2-core packs). Servers with more than 16 cores require additional 2-core packs. Datacenter licensing becomes cost-effective when running more than 8 VMs per physical host. The Server 2025 licenses can be stacked in the same system. As an example, a server with 32 physical CPU cores can stack two Windows Server 2025 licenses.

Client Access License (CAL) and Requirements

Windows Server 2025 requires CALs for every user or device accessing the server, regardless of whether the server runs on-premises or in a public cloud (Azure, AWS). CALs are not checked by the system but are legally required and enforced during Microsoft audits. Microsoft audits can result in significant penalties. Ensure all user accounts accessing Windows Servers have appropriate CAL coverage.

User CALs are named users accessing from any device. This is for remote workers or a mobile workforce that may log in from different devices. Device CALs are for shared workstations or kiosks. Multiple users can log in and work from the same device.

CAL version must match or exceed the server operating system version. This is known as the "downgrade right". You can run older server OS versions with newer CALs, but not vice versa. When migrating to new versions, you are required to repurchase all CALs and licences for the new version of Windows Server.

Microsoft 365 E3 and E5 licenses include Windows Server CAL-equivalent rights for any server OS version. This means:

  • M365 E3/E5 users: No separate Windows Server CALs required for those user accounts for the duration of the subscription
  • Non-M365 users: Require traditional Windows Server User CALs
  • The limitations for M365 are that RDS, and Microsoft SQL CALs that are not included

For detailed information refer to the Microsoft Windows Server 2025 Licensing Resources and Documents.

Directory Service

See: https://en.wikipedia.org/wiki/Directory_service
source: https://www.loginradius.com/glossary/directory-service

A Directory Service is software that manages the storage, retrieval, and organization of network resources and user information using a hierarchical tree structure. In general, most directory services use the LDAP protocol (Lightweight Directory Access Protocol) for querying and modifying directory entries. Major directory services include Microsoft Active Directory (Windows domain environments), OpenLDAP (open-source), and Microsoft Entra ID (formerly Azure Active Directory, cloud-based). Directory services are the foundation of enterprise IAM, providing centralized user management, authentication, and authorization.

Directory Service functions:

  • Storage: Hierarchical database for users, groups, devices, OUs
  • Query/Search: LDAP-based lookups (fast read access)
  • Authentication: Validate credentials against stored passwords
  • Authorization: Provide group memberships and attributes for access decisions

Microsoft Windows Domain

Source: https://en.wikipedia.org/wiki/Windows_domain

A Windows domain is a form of a computer network in which all user accounts, computers, printers and other security principals are registered with a central database located on one or more clusters of central computers known as domain controllers. Each person who uses computers within a domain receives a unique user account that can then be assigned access to resources within the domain. The concept of a Windows domain is in contrast with that of a workgroup in which each computer maintains its own database of security principals. A domain is a logical grouping of computers.

In a Windows domain, the directory resides on computers that are configured as domain controllers. A domain controller is a Windows server (or Linux/Unix with Samba server) that manages all security-related aspects between user and domain interactions, centralizing security and administration.

Active Directory vs Generic LDAP Directory Implementations

In Windows NT domains (NT 3.x and NT 4.0), administration focused primarily on users, groups, and computer accounts within individual domains. Active Directory introduced a hierarchical directory structure with organizational units (OUs), forests, trusts, and Group Policy, making large-scale administration significantly easier.

LDAP is a standard communications protocol for providing directory services. Some AD communication is based on the LDAPv3 (RFC 2251 and later RFC 4510) protocol; however, Microsoft extended AD with Microsoft-specific schema extensions, security models, protocols, and management features, making Active Directory a Microsoft-specific implementation rather than a generic LDAP directory service. Some of the changes and differences are:

  • Active Directory uses LDAP Distinguished Names (DNs) like other LDAP directories, but also assigns Windows Security Identifiers (SIDs) to security principals such as users, groups, and computers.
  • AD uses other protocols for many of its functions:
    • LDAP/LDAPS for directory access
    • Kerberos for authentication
    • DNS for service location
    • SMB and RPC for various directory functions and replication activities
  • AD has "Domains", "Trees", "Forests", and "Trusts", meaning it can create trust relationships between multiple domains
    • Active Directory provides a Global Catalog service that enables directory searches across the entire forest. Similar capabilities may exist in other LDAP directory implementations, but they are implementation-specific and not defined by LDAP itself.
  • AD has a multi-master replication architecture. Other LDAP directory implementations may also support multi-master replication, depending on the specific product and configuration.
  • Active Directory is tightly integrated with DNS and uses DNS SRV records for locating domain controllers and directory services. Other LDAP implementations may also integrate with DNS, but the dependency is typically less extensive.
    • Active Directory depends heavily on DNS for domain controller discovery, authentication, replication, and service location. A properly functioning AD environment requires correctly configured DNS services.
  • Group Policies are a Microsoft creation. Group Policy features include:
    • Group Policy Objects (GPOs)
    • Centralized desktop management
    • Security settings
    • Software deployment
    • Registry management
  • AD has extended the directory database schema with hundreds of Windows-specific attributes.
    • AD integrates directly with the Windows security model, including SIDs, access tokens, and NTFS permissions.
    • Other LDAP directory products implement their own access-control mechanisms that may differ significantly from Windows ACLs.

AD provides many tools for enterprises to manage users, systems, resources and configurations centrally, including Authentication and Authorization. Active Directory provides authentication logs, security auditing, and event records, but it is not considered a complete AAA accounting solution. Organizations that require detailed tracking of resource usage, privileged activity, or compliance reporting often supplement Active Directory with SIEM platforms such as Microsoft Sentinel or third-party auditing products. SMEs that use Microsoft Windows Server and AD often forgo accounting. Lack of Accounting may not be an option in industries where it is mandated as part of compliance requirements. Examples of Network Accounting systems include RADIUS accounting, TACACS+ accounting, SIEM platforms, and specialized privileged-access monitoring solutions.

Terminology:

Authentication is establishing a reasonable level of confidence that the entity is who or what it claims to be.
Authorization is the granting of permission to perform tasks or access resources based on one or more attributes of the entity requesting authorization
Accounting is the process of tracking, recording, and auditing user activities and system resource usage to ensure accountability and support security monitoring.
Auditing is a highly detailed account of the level of specifically what was accessed, when, and the results of the access.
