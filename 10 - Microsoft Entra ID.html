10 - Microsoft Entra ID

Source: https://learn.microsoft.com/en-us/entra/identity/domain-services/compare-identity-solutions

Active Directory Domain Services (AD DS) is Microsoft's traditional on-premises directory service, while Microsoft Entra ID is Microsoft's cloud-based identity and access management platform.

  • Microsoft Entra ID: Microsoft's identity and access management (IAM) and Identity as a Service (IDaaS) solution.

    • Provides authentication for multiple sources:
      • On-premises AD (Active Directory) via Entra Connect
      • Web applications via App Registrations
      • Other identity providers, such as Google and Facebook via External Identities
      • All Microsoft 365 and Azure products, such as Office 365, Microsoft Azure, Dynamics 365, Teams, SharePoint, etc.
      • Thousands of third-party SaaS applications that integrate with Microsoft Entra ID in Azure Marketplace
    • Microsoft Entra ID can be synchronized with an on-premises AD DS environment to provide a single identity to users that works natively in the cloud.

  • Microsoft Entra Domain Services: Provides managed domain services with a subset of fully compatible traditional AD DS features

    • Microsoft Entra Domain Services provides:
      • Domain joins for Azure virtual machines and legacy applications without deploying domain controllers
      • Group policies
      • LDAP
      • Kerberos and NTLM authentication
    • Domain Services integrates with Microsoft Entra ID, which itself can synchronize with an on-premises AD DS environment.
    • Domain Services provides a smaller subset of features to traditional self-managed AD DS environment, which reduces some of the design and management complexity. For example, there are no AD forests, custom forest trusts, domain controller deployment, sites, or replication-topology design tasks to manage
    • Use cases:
      • Moving traditional workloads to the cloud; can be used for "lift-and-shift" migrations from on-prem AD DS to Azure
      • Maintain compatibility with existing on-premises applications
      • Synchronize on-premises AD DS identities to Microsoft Entra ID using Microsoft Entra Connect, which can then be consumed by Microsoft Entra Domain Services

A Microsoft Entra tenant is a dedicated instance of Microsoft Entra ID that represents an organization. A tenant is typically created when an organization signs up for Microsoft cloud services such as Azure, Microsoft 365, or Intune. Administrators can create and manage multiple tenants, each acting as a separate identity directory with its own users, groups, applications, and policies.

Hybrid Windows AD DS and Entra ID

Considering all available options for authentication and identity management in the Microsoft environment, Microsoft provides general guidelines on how to select the correct solution or which combinations to use when designing an architecture under the Microsoft Learn article Choose the right authentication method for your Microsoft Entra hybrid identity solution. In summary, they provide the following decision tree:

Federation services are more advanced. When using federation, Microsoft Entra ID hands off the authentication process to a separate trusted authentication system, such as on-premises Active Directory Federation Services (AD FS), to validate the user's password. The authentication system can provide other advanced authentication requirements, such as third-party multi-factor authentication. This is out of the scope for this course, and the details will not be discussed here.

In the above decision tree, there are only two options for syncing on-premises AD DS and Entra ID, which can be utilized by themselves or in combination:

  1. Microsoft Entra password hash synchronization
    • Install the Entra Connect utility on the on-premises domain controller and connect to the Entra ID service in the cloud via the software, selecting the appropriate options
    • Entra Connect will hash all account passwords from the local AD DS and upload them to Azure, updating changes every 2 minutes
    • Users can use the same username and password to authenticate to the on-prem AD DS or in the cloud to any connected application via Entra ID
    • Enables the following security features:
      • Leaked Credential Reports (compare the hash with the database of leaked credentials and facilitate altering, blocking, or password change)
      • Smart lockout: Anti-brute-force and credential stuffing attack, prevents legitimate user lockout
      • Optional: Seamless SSO: allows users logged on to a domain-joined system (corporate computer) to access cloud resources without having to log in (can be selected as an option via Entra Connect utility)
    • For guidelines, requirements, and procedures, refer to the Microsoft Learn article on Implement password hash synchronization with Microsoft Entra Connect Sync
  2. Microsoft Entra pass-through authentication
    • Install the Entra Connect utility on the on-premises domain controller and connect to the Entra ID service in the cloud via the software, selecting the appropriate options
    • Install two or more authentication agents on the on-premises domain controllers
    • Agents maintain a consistent connection to Entra ID and listen for authentication requests
    • Users can authenticate to the on-premises AD DS directly, or via Entra ID (from the cloud)
    • Entra ID will use public key encryption (TLS1.2) to pass credentials to the agents running on on-premises servers to be validated; the results will be relayed back to Entra ID via the agent
    • Enables the following security features:
      • Smart lockout
      • Optional: Seamless SSO
    • For guidelines, requirements, and procedures, refer to the Microsoft Learn article on Microsoft Entra pass-through authentication: Quickstart.
